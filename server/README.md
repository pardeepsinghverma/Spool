# The licence token format

**The licence server itself is not here.** It is a plain PHP + MySQL
application, and on this machine it lives at:

```
c:\laragon\www\spool
```

Read [`c:\laragon\www\spool\README.md`](file:///c:/laragon/www/spool/README.md)
for the routes, the UPI payment setup, the deployment, the database and every
trap that has been found in it. Nothing about running the server is documented
in this directory any more.

What stays here is the one thing the app repository genuinely owns: **a
reference implementation of the token format, and a test that pins it.**

---

## Why this survives the move

`LicenseGuard.kt` verifies a token that some server signed. The Kotlin cannot be
reached by `node --test`, and the PHP that signs it now lives outside this
repository — so without this directory there would be nothing in the app's own
test suite that fails when the format drifts.

```
npm test -- "tests/licenceToken.test.mjs"
```

Sixteen cases, no dependencies, about a tenth of a second. They assert the
things both implementations must agree on:

- the token is `base64url(payloadJson) "." base64url(derSignature)`;
- **the signature covers the ASCII of the first segment**, not the JSON it
  decodes to — and a re-ordered payload must *not* verify;
- the signature is **DER**, and is accepted by Node's verifier, which wants
  exactly what the Android JCA wants;
- `exp` is `paid_through + GRACE_MS`, never `paid_through`;
- a month is a calendar month (31 Jan + 1 month = 3 Mar), because the PHP
  implementation was written to match this behaviour rather than fix it.

The DER round trip runs a hundred times on purpose. A P-256 signature needs a
leading zero byte whenever a half's top bit is set — one time in two — and
leading zeros stripped when it is not, so a single pass proves very little.

**`rawToDer` in [`src/license.js`](src/license.js) is JavaScript-only.**
WebCrypto emits a raw `r || s` pair and the JCA wants DER, so the JS has to
convert. PHP's `openssl_sign` on an EC key already emits DER — the PHP does
*not* convert, and making it "consistent" with this file would break every
licence. That asymmetry is the single most likely thing for a future reader to
get wrong, which is why it is stated in both places.

Verified in both directions: PHP and this file emit **byte-identical heads** for
identical claims (including the `/` and `+` that `JSON_UNESCAPED_SLASHES`
exists for), and Node verifies PHP-minted tokens against a key generated by
`keygen.mjs`.

---

## `keygen.mjs`

Still works and still prints a usable pair. `php tools/keygen.php` in the server
directory does the same job and is the one the server's own README points at —
use whichever is to hand, they produce the same thing. The private half goes to
the server, the public half into the APK as `SPOOL_LICENCE_KEY`.

> Losing the private key is not recoverable. Every token already on a phone
> keeps verifying until it expires and no new one can ever be signed, so every
> subscriber lapses silently over the following days and the only fix is a new
> build.

## What used to be here

A Cloudflare Worker with D1, a PHP variant, and a single-file cPanel variant —
three implementations of one contract. They are gone. Running three servers that
must stay byte-compatible with each other and with `LicenseGuard.kt` was three
ways for the format to drift and one benefit, and the PHP application now at
`c:\laragon\www\spool` deploys to ordinary hosting, which was the only thing the
cPanel variant offered over it.
